# 모바일 내비게이션과 입력 확대 방지 설계

## 목표

모바일에서 워크스페이스 사이드바가 본문 폭을 차지하지 않도록 하고, 사용자가 햄버거 버튼으로 메뉴를 열고 닫게 한다. 입력란 포커스 시 브라우저가 자동으로 화면을 확대하지 않게 한다. 화이트보드 문서 카드도 프로젝트 카드처럼 카드 빈 영역에서 열 수 있어야 한다.

## 동작

- 640px 미만에서는 기본 사이드바를 숨기고 본문 상단에 메뉴 버튼을 표시한다.
- 메뉴 버튼은 접근 가능한 모달 서랍을 연다. 닫기 버튼, 바깥 영역 클릭, `Escape`, 메뉴 이동 또는 워크스페이스 선택으로 닫힌다.
- 서랍 안에서는 사이드바 접기·크기 조절 컨트롤을 숨겨 닫기 버튼과 조작이 겹치지 않게 한다.
- 640px 이상에서는 기존 사이드바 접기·크기 조절 동작을 유지한다.
- 640px 미만에서는 `input`, `textarea`, `select` 글꼴을 최소 16px로 설정해 iOS Safari의 포커스 확대를 막는다. 사용자가 브라우저 확대를 사용할 수 있도록 viewport의 확대 제한은 추가하지 않는다.
- 화이트보드 카드의 제목 버튼은 `after:absolute after:inset-0`으로 카드 전체 클릭 영역을 제공한다. 메뉴는 카드 링크보다 위에 유지한다.

## 범위와 계약

- 변경 범위: 인증된 워크스페이스 레이아웃, 내비게이션 접근성 문구, 앱 전역 폼 컨트롤 CSS.
- API, 데이터 모델, 권한, 저장 동작은 변경하지 않는다.
- 프로젝트·멤버·설정 내비게이션과 사이드바 내부의 워크스페이스 전환, 초대, 생성 동작을 보존한다.

## 검증 계획

- 레이아웃 검증: 모바일 메뉴 트리거 표시, 열기/닫기, 내비게이션 이동 후 닫힘, 데스크톱 메뉴 버튼 미표시.
- 스타일 검증: 작은 화면에서 폼 컨트롤이 16px이고 데스크톱 스타일은 그대로인지 확인한다.
- 카드 검증: 화이트보드 카드의 전체 영역 링크와 메뉴의 독립 조작을 확인한다.
- 타입 검사와 클라이언트 lint/build를 수행한다.
