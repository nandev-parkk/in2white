# 보기 전환 선택 표시 이동 설계

## 목표

프로젝트와 화이트보드 목록의 카드·테이블 보기 버튼에서 흰색 선택 표시가 선택 방향으로 자연스럽게 이동한다. 보기 전환과 버튼의 접근성 동작은 현재와 같다.

## 현재 동작과 변경 설계

- 공용 `ViewToggle`은 선택된 버튼에 각각 흰 배경과 테두리·그림자를 적용한다. 값이 바뀌면 흰 배경이 즉시 다른 버튼에 나타난다.
- 버튼 그룹 안에 장식용 선택 표시를 하나 배치한다. 표시의 크기와 모양은 현재 선택 버튼과 같게 하고, `value`가 `table`일 때 버튼 너비와 간격만큼 오른쪽으로 이동시킨다.
- 위치 변화에는 200ms `ease-in-out` 전환을 적용한다. 사용자가 움직임 줄이기를 설정했다면 전환 없이 즉시 위치를 바꾼다.
- 버튼은 표시 위에 유지한다. 기존 `onChange`, `aria-pressed`, 접근성 이름과 키보드 포커스 표시를 유지한다. 장식 요소는 접근성 트리에서 숨긴다.

## 변경 범위

- `frontend/src/shared/ui/view-toggle.tsx`에서 선택 표시와 위치 전환을 구현한다.
- `frontend/src/shared/ui/view-toggle.test.tsx`에서 값 변경 시 단일 선택 표시가 이동 상태로 바뀌고 버튼의 `aria-pressed`가 유지되는지 확인한다.
- 프로젝트·화이트보드 목록은 공용 컴포넌트를 사용하므로 호출부 변경은 필요하지 않다. 새 의존성은 추가하지 않는다.

## 권한·오류 계약

서버 요청, 권한 검사, 오류 처리에는 변경이 없다. `ViewToggle`의 `value`와 `onChange` 계약도 유지한다.

## 검증

해당 컴포넌트 테스트를 먼저 실패 상태로 확인한 뒤 구현한다. 이후 프런트엔드 테스트, 린트, 빌드를 실행하고 카드↔테이블 전환 및 움직임 줄이기 동작을 확인한다.
