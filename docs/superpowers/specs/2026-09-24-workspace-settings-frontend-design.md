# 워크스페이스 설정 프론트엔드 설계

## 목표

워크스페이스 소유자가 워크스페이스 이름을 변경하고, 기본 워크스페이스가 아닌 경우 워크스페이스를 삭제할 수 있는 설정 화면을 제공한다. 현재 워크스페이스 셸과 사이드바를 재사용하고, 기존 백엔드 API에 연결한다.

성공 조건:

- 소유자는 사이드바에서 설정 화면으로 이동해 이름을 저장할 수 있다.
- 소유자는 기본 워크스페이스가 아닌 워크스페이스를 확인 대화상자에서 삭제할 수 있다.
- 멤버에게 설정 메뉴와 변경 UI를 노출하지 않으며, 직접 URL 접근도 권한 거부 상태로 처리한다.
- 기본 워크스페이스는 이름 변경이 가능하고 삭제 UI는 표시하지 않는다.

## 접근안

### 선택: 독립 설정 라우트와 페이지

새 경로 /workspaces/$workspaceId/settings에 전용 페이지를 둔다. 기존 AuthenticatedWorkspaceLayout, 워크스페이스 요약 쿼리, workspace 엔티티와 mutation 훅을 재사용한다. 설정은 프로젝트·멤버 목록과 목적 및 권한이 다르고 제품 명세와 Figma도 별도 페이지를 가리킨다.

### 제외: HomePage 안에 설정 화면 삽입

기존 HomePage의 프로젝트·멤버 콘텐츠 분기에 설정을 추가하면 화면 종류와 관리자 권한 분기가 한 페이지에 섞인다. 설정 전용 경로를 두는 편이 기존 페이지 구조와 제품 명세에 맞는다.

## 화면과 동작

Figma 설정 프레임은 1440×500이며, 왼쪽 240px 사이드바와 좌측 정렬된 설정 콘텐츠로 구성된다.

- 상단 페이지 제목은 설정이다.
- 일반 섹션은 워크스페이스 이름 라벨, 400px 입력, 저장 버튼을 포함한다. 입력 높이와 버튼 높이는 각각 36px이다.
- 이름은 기존 백엔드 스키마와 일치하게 앞뒤 공백을 제거한 후 1~255자로 검증한다. 값이 바뀌지 않았거나 저장 중이면 저장을 비활성화한다.
- 기본 워크스페이스가 아닌 경우에만 위험 구역을 표시한다. 위험 배경 안에 삭제 설명과 Destructive 버튼을 배치한다.
- 삭제 버튼은 Figma의 360×208 확인 모달을 연다. 32px 안쪽 여백을 두고 현재 워크스페이스 이름을 포함한 제목과 프로젝트·화이트보드 문서가 함께 삭제되며 되돌릴 수 없다는 안내를 표시한다. 취소는 모달을 닫고, 확인은 삭제 요청을 보낸다.
- 삭제 성공 시 워크스페이스 목록 쿼리를 갱신하고 기본 경로로 이동한다. 이름 변경 성공 시 같은 쿼리를 갱신해 사이드바 이름도 최신 상태로 만든다.
- 입력·버튼·모달은 기존 공유 UI 컴포넌트와 디자인 토큰을 재사용한다. Figma 응답의 Tailwind 프로토타입을 그대로 복사하거나 새 UI 라이브러리를 추가하지 않는다.

## 권한과 오류 계약

- 라우트는 기존 인증 가드를 사용한다. 비인증 사용자는 기존 로그인 흐름으로 이동한다.
- 설정 사이드바 항목은 현재 워크스페이스 역할이 owner일 때만 표시한다. 새 라우트도 역할을 확인하며, 멤버의 직접 URL 접근은 기존 WorkspaceAccessDeniedPage를 사용하고 프로젝트 화면으로 돌아가게 한다.
- 화면의 역할 확인은 사용자 경험용이다. 권한, 워크스페이스 존재 여부, 기본 워크스페이스 삭제 제한은 백엔드 검증을 최종 기준으로 둔다.
- 이름 검증·권한·네트워크 오류가 발생하면 기존 API 오류 표시 규칙을 사용한다. 저장 실패 시 입력값을 유지한다. 삭제 실패 시 확인 모달을 유지하고 성공 경로로 이동하지 않는다.
- 백엔드 API 계약은 변경하지 않는다.
  - PATCH /workspaces/:workspaceId에 { name }을 보내고 { workspace } 응답을 받는다.
  - DELETE /workspaces/:workspaceId 성공은 204 No Content다. 기본 워크스페이스 삭제는 서버에서 거부된다.

## 변경 범위

- 워크스페이스 API 엔티티에 이름 변경·삭제 요청과 타입을 추가한다.
- 기존 워크스페이스 feature의 TanStack Query 훅에 두 mutation을 추가하고 성공 시 워크스페이스 쿼리를 무효화한다.
- 설정 페이지와 보호된 라우트를 추가하고 기존 설정 메뉴를 새 라우트에 연결한다.
- 사이드바에서 비소유자의 설정 메뉴를 숨긴다. 프로젝트·멤버 페이지에서도 사이드바의 설정 이동이 동작하도록 라우트 콜백을 연결한다.
- API·mutation·설정 UI 및 라우트 동작 테스트를 추가하거나 갱신한다.
- 백엔드 코드와 DB 스키마는 변경하지 않는다.

## 검증 계획

- API 요청 경로·메서드·본문·응답 처리의 단위 검증.
- 이름 저장, 변경 없음·저장 중 상태, 삭제 모달의 취소·확인·실패 동작, 기본 워크스페이스 및 멤버 권한의 화면 검증.
- 프로젝트·멤버·설정 사이드바 이동과 삭제 후 기본 경로 이동 검증.
- 프론트엔드 lint와 build 실행.
- 1440px Figma 프레임 기준으로 사이드바, 섹션 간격, 400px 입력, 위험 구역과 모달을 시각적으로 비교한다.
