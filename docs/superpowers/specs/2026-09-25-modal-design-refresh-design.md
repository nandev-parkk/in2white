# 모달 디자인 정비 설계

## 목표

기존 확인 모달은 행동의 위험을 아이콘과 정돈된 중앙 정렬로 빠르게 이해할 수 있게 하고, 입력 모달은 같은 시각적 규칙으로 더 편안하게 읽고 작성할 수 있게 한다. 삭제·내보내기·생성·수정·검색 동작은 그대로 유지한다.

## 적용 범위

| 유형          | 화면                                                        | 아이콘 및 구성                                                              |
| ------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------- |
| 삭제 확인     | 워크스페이스 설정                                           | `CircleAlert`와 위험 색상. 삭제 대상, 영향 범위, 복구 불가 안내를 중앙 정렬 |
| 삭제 확인     | 프로젝트                                                    | `FolderX`와 위험 색상. 제목, 대상 이름, 오류를 중앙 정렬                    |
| 삭제 확인     | 화이트보드                                                  | `FileX`와 위험 색상. 제목, 대상 이름, 오류를 중앙 정렬                      |
| 내보내기 확인 | 멤버 목록                                                   | `UserRoundMinus`와 위험 색상. 제목, 접근 권한 안내, 오류를 중앙 정렬        |
| 입력          | 워크스페이스 생성, 프로젝트 생성·수정, 화이트보드 생성·수정 | 아이콘 없이 제목·짧은 설명·필드·버튼 사이의 간격을 통일                     |
| 검색·선택     | 멤버 추가                                                   | 입력 모달과 제목·여백을 맞추되 검색 결과 목록의 밀도와 동작은 유지          |

## 시각 규칙

### 확인 모달

- 기존 `Dialog` 기본 요소를 사용한다. 확인 영역의 아이콘, 제목, 설명, 경고·오류 문구는 가운데 정렬한다. 아이콘은 장식으로 처리해 보조 기술에서 중복 낭독되지 않게 한다.
- 아이콘은 위험 색상의 옅은 원형 배경 안에 놓고, 제목은 약 20px의 강한 글꼴로 표시한다. 설명은 좁은 줄 폭과 충분한 행간을 사용한다. 긴 대상 이름은 줄바꿈한다.
- 워크스페이스의 복구 불가 안내는 별도의 옅은 위험 배경에 중앙 정렬한다. 삭제·내보내기 실패 문구는 `role="alert"`를 유지한다.
- 버튼 영역은 확인 내용과 구분하고 오른쪽 정렬을 유지한다. 모바일에서는 화면 양옆에 여유를 두며 내용이 길어져도 스크롤할 수 있게 한다.

### 입력·검색 모달

- 제목과 입력 필드는 왼쪽 정렬한다. 제목 아래에 목적을 알려주는 짧은 설명을 배치하고, 제목·필드·하단 버튼 사이의 간격과 패딩을 통일한다.
- 기존 입력 컴포넌트, 라벨, 오류 메시지, 검증 규칙을 재사용한다. 필드 간 간격과 하단 경계선을 조정해 시각적 계층을 분명히 한다.
- 멤버 검색 모달은 같은 제목·바깥 여백을 적용한다. 검색창, 목록, 빈 상태, 페이지 이동의 밀도와 구조는 유지한다.
- 밝은 화면과 어두운 화면 모두 기존 의미 색상 토큰을 사용한다. 새 이미지나 의존성은 추가하지 않는다.

## 동작·권한·오류 계약

- 생성·수정·삭제·내보내기·멤버 추가의 제출 값, API 호출, 권한 조건, 로딩 중 비활성화, 취소, 닫기, 포커스 복귀를 변경하지 않는다.
- 기존 필수값·길이 검증과 서버 오류 표시를 유지한다. 모달에는 접근 가능한 제목이 있어야 하며, 설명과 오류의 의미도 보존한다.
- 공유 `Dialog`의 기본 동작은 유지하고, 각 모달의 배치만 필요한 만큼 조정한다. 실제로 쓰이는 아이콘 유형만 구현한다.

## 검증 계획

1. 관련 모달의 기존 테스트로 제출·취소·로딩·오류·접근 가능한 제목 동작을 확인한다. 변경된 확인 모달에는 아이콘이 장식으로 처리되고 내용과 버튼 영역이 분리되는지 확인하는 최소 검증을 추가한다.
2. 프런트엔드의 테스트, 린트, 타입 검사 포함 빌드를 실행한다.
3. Storybook 또는 실행 화면에서 확인 모달과 입력 모달을 좁은 화면 및 밝은·어두운 테마로 확인한다.
