# 워크스페이스 설정 보호와 삭제 UI 설계

## 목표

워크스페이스 이름을 바꾼 직후 사용자가 성공을 알아볼 수 있게 하고, 기본 워크스페이스의 이름 변경을 화면과 API 양쪽에서 막는다. 삭제 영역과 확인 모달의 시각적 위계를 정리해 삭제 대상과 영향을 쉽게 이해하게 한다.

## 현재 상태

- 프론트엔드 `WorkspaceSummary.isDefault`로 기본 워크스페이스를 구분한다.
- 일반 설정 화면은 이름 변경 성공 후 토스트를 띄우지 않는다.
- 백엔드 `updateWorkspace`는 소유자 여부를 확인하지만 기본 워크스페이스인지 확인하지 않는다.
- 삭제 기능은 확인 모달과 위험 구역이 있으며, 기본 워크스페이스 삭제는 서버가 이미 거부한다.

## 동작 설계

### 이름 변경

- 저장 성공 시 공용 토스트로 `워크스페이스 이름을 변경했어요`를 표시한다.
- `isDefault`인 경우 이름 입력을 읽기 전용으로 보여주고 `기본 워크스페이스의 이름은 변경할 수 없어요.` 안내를 제공한다. 저장 버튼은 사용할 수 없게 한다.
- 백엔드 `updateWorkspace`도 기본 워크스페이스 변경을 거부한다. 소유자 확인 뒤 `isDefault`를 검사하고, 기본 워크스페이스이면 HTTP 403과 `WORKSPACE_DEFAULT_UPDATE_FORBIDDEN` 코드를 반환한다.
- 비소유자·없는 워크스페이스의 기존 403·404 계약은 유지한다.

### 삭제 UI

- 삭제가 성공하면 `워크스페이스를 삭제했어요` 토스트를 띄운다. 실패 시에는 기존처럼 모달 안에 오류를 표시하고 성공 토스트는 띄우지 않는다.
- 기존 위험 구역을 카드 형태로 정돈하고, 삭제 제목·영향 설명·파괴적 버튼을 분리해 배치한다.
- 확인 모달은 경고 아이콘과 워크스페이스 이름을 먼저 보여주고, 프로젝트와 화이트보드 문서가 함께 삭제되며 복구할 수 없다는 내용을 강조한다.
- 기존 공용 디자인 토큰과 UI 컴포넌트를 사용한다. 삭제 API 계약과 확인 단계는 바꾸지 않는다.

## 범위

- 프론트엔드 설정 화면과 해당 컴포넌트 테스트
- 백엔드 워크스페이스 업데이트 서비스, 오류 메시지, API 테스트
- 설계·구현 계획 문서

새 의존성, 워크스페이스 조회 API 변경, 기본 워크스페이스 삭제 정책 변경은 범위에 포함하지 않는다.

## 권한·오류 계약

- Owner가 기본 워크스페이스 이름 변경을 요청하면 HTTP 403 `WORKSPACE_DEFAULT_UPDATE_FORBIDDEN`을 반환한다.
- Owner가 일반 워크스페이스 이름 변경을 요청하면 기존 성공 응답을 반환한다.
- 비소유자 및 존재하지 않는 워크스페이스는 기존 `WORKSPACE_UPDATE_FORBIDDEN` 및 `WORKSPACE_NOT_FOUND` 응답을 유지한다.

## 검증 계획

- API 회귀 테스트에서 기본 워크스페이스 변경 거부와 일반 워크스페이스 변경 성공을 확인한다.
- UI 테스트에서 기본 워크스페이스 읽기 전용 상태, 성공 토스트, 삭제 확인 정보를 확인한다.
- 관련 테스트와 전체 테스트, lint, build를 실행하고 결과를 구현 계획에 기록한다.
