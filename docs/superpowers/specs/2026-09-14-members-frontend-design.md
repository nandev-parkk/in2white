## 화면과 동작

`/workspaces/$workspaceId/members` 경로를 추가하고 프로젝트·멤버 사이드바를 실제 경로와 연결한다. 워크스페이스 전환 시 현재 목록 종류를 유지한다. 기존 HomePage의 공통 셸을 재사용하고 검색·페이지·모달 상태는 워크스페이스 전환 시 초기화한다.

목록은 피그마의 List Cell을 사용한다. 이름, 이메일, 32px 아바타, 소유자/멤버 배지, 합류일, 소유자 전용 내보내기 버튼을 표시한다. 데스크톱 기준 사이드바 240px, 본문 좌우 20px, 상단 24px, 검색 폭 320px, 컨트롤 높이 36px, 행 높이 약 62px를 따른다. 작은 화면은 기존 축소 사이드바를 유지하고 행 메타데이터를 재배치해 가로 넘침을 방지한다.

이름·이메일 검색은 300ms 디바운스 후 서버에 전달하고 페이지를 1로 초기화한다. 페이지 크기는 기존 API 기본값 20을 사용하며 페이지 수는 서버 응답으로 결정한다. 피그마의 예시 5개 행이나 5페이지를 데이터로 고정하지 않는다. 합류일은 한국 시간 기준 `yyyy.MM.dd` 형식으로 표시한다.

추가 모달은 폭 380px, 패딩 24px로 구성한다. 소유자만 열 수 있다. 사용자 검색 결과에서 사용자를 선택하면 즉시 추가하고 모달은 열린 상태를 유지한다. 이미 멤버인 행은 표시하되 선택을 차단한다. 요청 중 중복 선택을 막고 성공 시 목록·검색 결과·사이드바 미리보기를 갱신하며 성공 토스트를 표시한다.

내보내기 모달은 폭 360px, 패딩 32px를 기준으로 대상 이름과 접근 권한 상실 안내, 취소·내보내기 버튼을 제공한다. 명시적 확인 후 DELETE를 호출한다. 성공 시 모달을 닫고 관련 조회를 갱신한다. 마지막 페이지가 비면 유효한 이전 페이지로 이동한다. 소유자 자신에게는 내보내기 버튼이 없다. 피그마에 없는 본인 탈퇴 UI는 이번 범위에서 제외한다.

## API와 권한·오류 계약

기존 API를 그대로 사용한다.

- `GET /workspaces/:workspaceId/members?search=&page=1&limit=20`: `{ members: [{ userId, name, email, role, joinedAt }], pagination }`
- `POST /workspaces/:workspaceId/members`, body `{ userId }`: 201 `{ member }`
- `DELETE /workspaces/:workspaceId/members/:userId`: 204

추가 제안 API: `GET /workspaces/:workspaceId/member-candidates?search=&page=1&limit=20`.

- 해당 워크스페이스 소유자만 전체 사용자 검색 가능. 비로그인은 401, 비소속자는 404 `WORKSPACE_NOT_FOUND`, 일반 멤버는 403 `MEMBER_SEARCH_FORBIDDEN`.
- 기존 listQuerySchema로 검색어 최대 100자, page 최소 1, limit 1~100을 검증한다. 잘못된 입력은 기존 400 계약을 따른다.
- 응답: `{ users: [{ id, name, email, isMember }], pagination: { page, limit, total, totalPages } }`. 비밀번호 해시 등 내부 필드는 반환하지 않는다.
- 이름·이메일 부분 검색, 검색 특수문자는 기존 검색 유틸리티로 이스케이프한다. 이름·사용자 ID 순으로 안정 정렬한다. 빈 검색은 첫 페이지를 반환한다. 후보 모달에서 페이지 이동을 제공한다.
- 기존 멤버도 반환하고 `isMember`로 선택을 차단한다. 스키마 변경·마이그레이션은 필요 없다.

조회 실패는 재시도 UI, 추가·삭제 실패는 모달 내부 오류를 표시한다. 409 중복 추가와 404 대상 멤버 없음은 최신 목록을 다시 조회한다. 워크스페이스 접근 상실은 기존 접근 거부 화면으로 전환한다. 인증 만료 처리는 기존 인증 인터셉터를 따른다. 오류 응답의 내부 상세를 사용자에게 노출하지 않는다.

## 구현 구조와 재사용

- `entities/member`: 요청 함수와 타입
- `features/member`: 조회·변경 훅, 목록과 모달, 메시지
- `routes/workspaces/$workspaceId/members.tsx`: 인증 경로
- 기존 HomePage와 프로젝트 경로: 공통 내비게이션 연결
- 기존 Sidebar, ListCell, Avatar, Badge, Search, Pagination, Dialog, Button, Skeleton, Toast 재사용
- UserPicker는 실제 비활성화·키보드 선택·로딩·오류·빈 결과·페이지 이동을 지원하도록 호환 가능한 확장
- 쿼리 키에 사용자 ID·워크스페이스 ID·검색·페이지를 포함한다. 워크스페이스 전환 중 이전 응답이 새 화면에 섞이지 않도록 한다.
- 서체는 기존 Pretendard 및 프로젝트 토큰을 유지한다. 아이콘은 피그마와 모양이 일치하는 기존 Lucide만 재사용하고 불일치 에셋은 원본으로 확인한다.

## 검증

API 요청·검색·페이지 초기화·권한별 액션·중복 제출·추가·삭제 성공/실패·접근 상실·경로 전환을 Vitest/Testing Library로 검증한다. 사용자 검색 API는 권한, 입력 검증, 반환 필드, 기존 멤버 표시, 검색과 페이지 처리를 서비스·HTTP 테스트로 검증한다.

프론트엔드 전체 테스트·린트·빌드, 변경 파일 포맷, 백엔드 테스트·린트·빌드와 diff 검사를 실행한다. 브라우저에서 데스크톱과 모바일, 목록·모달·로딩·빈 결과·토스트를 피그마와 비교한다. 테스트 계정 환경에 대한 결과와 모의 응답 기반 검증을 구분해 기록한다.
