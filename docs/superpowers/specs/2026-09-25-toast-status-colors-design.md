# 토스트 상태 색상 디자인

## 목표

성공·오류·정보·경고 토스트의 테두리와 메시지 색상을 각 토스트의 아이콘 색상과 일치시킨다. 밝은 테마에서 메시지와 배경의 대비는 일반 텍스트 기준 4.5:1 이상으로 유지한다.

## 현행 구조와 변경 범위

- 프런트엔드의 `frontend/src/shared/ui/toast.tsx`가 Sonner 토스트 네 유형의 아이콘과 배경을 한곳에서 지정한다.
- `frontend/src/app/styles/index.css`에 상태 색상과 밝은·어두운 테마 토큰이 있다.
- 피그마 [in2white Design System](https://www.figma.com/design/Dimhltnal74SHy2NcLz1Lf/in2white?node-id=46-48)의 `Components > Toast`에 네 유형의 기존 컴포넌트가 있다. 새 컴포넌트는 만들지 않는다.

## 디자인과 동작

각 유형의 토스트 전체에 1px 실선 테두리를 적용하고, 제목과 설명 텍스트 및 아이콘에 같은 전경색을 사용한다. 배경색, 너비, 위치, 지속 시간, 일반 토스트와 로딩 토스트의 스타일은 유지한다.

| 유형 | 밝은 테마 전경·테두리  | 어두운 테마 전경·테두리 | 기존 배경                  |
| ---- | ---------------------- | ----------------------- | -------------------------- |
| 성공 | `oklch(0.52 0.16 144)` | `status-success`        | `status-success-subtle-bg` |
| 오류 | `status-danger`        | `status-danger`         | `status-danger-subtle-bg`  |
| 정보 | `oklch(0.54 0.22 261)` | `status-info`           | `status-info-subtle-bg`    |
| 경고 | `oklch(0.54 0.128 56)` | `status-warning`        | `status-warning-subtle-bg` |

밝은 테마의 성공·정보·경고에는 토스트 전용 색상 토큰을 추가한다. 기존 상태 토큰을 바꾸면 다른 화면에도 영향을 주므로 유지한다. 현재 배경색과 위 전경색의 계산 대비는 성공 4.77:1, 오류 4.76:1, 정보 4.64:1, 경고 4.80:1이다. 어두운 테마에는 기존 상태 색상을 사용한다.

피그마에서는 기존 `Semantic=Success`, `Semantic=Danger`, `Semantic=Info`, `Semantic=Warning` 컴포넌트의 테두리·레이블·아이콘을 맞춘다. 밝은 테마용 토스트 색상 변수 세 개를 추가하고 어두운 테마 값은 기존 상태 변수에 연결한다. 기존 인스턴스는 컴포넌트 변경을 따르게 한다.

## 권한·오류 계약

애플리케이션의 권한, API, 오류 처리 계약은 바뀌지 않는다. 피그마 파일에 쓰기 권한이 없거나 편집이 실패하면 중복 컴포넌트를 만들지 않고 실패 지점과 코드 반영 상태를 보고한다.

## 검증

- 기존 토스트 테스트를 실행해 렌더링과 줄바꿈 회귀를 확인한다.
- 프런트엔드 린트와 빌드를 실행해 Tailwind 클래스와 타입 오류를 확인한다.
- 밝은·어두운 테마에서 네 유형의 실제 텍스트·보더·아이콘 색상을 확인한다.
- 피그마에서 네 컴포넌트의 테두리·텍스트·아이콘 색상 바인딩과 기존 인스턴스 연결을 확인한다.
